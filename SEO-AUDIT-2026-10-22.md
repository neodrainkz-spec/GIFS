## Подтверждённые проблемы и выполненные изменения

1. В ready/ и v13/ обнаружены копии contact.html, neodrain.html и credits.html без canonical. Их содержимое body совпадает с соответствующими корневыми страницами после нормализации относительных путей. Добавлен canonical на существующие корневые страницы — только в gh-pages, где эти копии находятся.
2. ready/services.html и v13/services.html полностью совпадают друг с другом. Для пары добавлен canonical на ready/services.html. На корневую services.html их не объединяли: содержимое различается.
3. В шести корневых страницах og:locale изменён с ru_RU на ru_KZ в обеих ветках, в соответствии с регионом сайта.
4. README уточняет, какую публикацию обслуживает репозиторий.

Все изменения ограничены метаданными и документацией. Body страниц, стили, изображения, JavaScript и Google verification HTML сохранены. Redirect/noindex не добавлялись. Наличие нескольких h1 в исходном HTML главной gifs.kz связано с несколькими разделами интерфейса и само по себе не признано ошибкой. Отсутствие явного robots meta у внутренних страниц тоже не является ошибкой: запрет индексации не обнаружен.

## Риск конкуренции публикаций

Старая главная GitHub Pages уже индексируется отдельно, а оба сайта предлагают услуги той же студии. Риск конкуренции за брендовые и коммерческие запросы подтверждён; фактическую потерю трафика или присутствие обоих сайтов в одной выдаче эти данные не доказывают.

Основной адрес текущей студии установлен как https://gifs.kz/. Политика архивной публикации и полное соответствие старых URL новым не определены. Поэтому общая смена canonical, перенаправления или исключение всей старой версии из индекса не выполнены. Ряд старых страниц не имеет отдельного эквивалентного URL на gifs.kz; назначение всем одного canonical было бы некорректно.

## Конкретные действия для действующей публикации

1. В Google Search Console проверить/подключить свойство sc-domain:gifs.kz через DNS либо URL-prefix https://gifs.kz/. Для HTML-способа разместить именно файл, выданный Google для нужного свойства и аккаунта, и выполнить проверку в Search Console. Нельзя утверждать, что старый файл GitHub автоматически подтверждает домен.
2. После подтверждения отправить https://gifs.kz/sitemap.xml в соответствующее свойство и проверить главную и пять внутренних страниц через URL Inspection, включая Google-selected canonical.
3. Сохранить текущие правильные canonical, title, description, og:url, robots.txt и существующие 301 с HTTP/www/index.html. Замена их на GitHub Pages не нужна.
4. Установить репозиторий/каталог публикации и её процесс сборки. Изменения в neodrainkz-spec/GIFS не заменяют эту работу.
5. Для старой публикации согласовать таблицу URL: главная → https://gifs.kz/; кейс NeoDrain → https://gifs.kz/cases/neodrain/. Услуги, атмосфера и контактный бриф требуют отдельного решения, так как страницы различаются и есть разделы с #fragment. Фрагменты не использовать как canonical отдельных страниц.
6. Если GitHub Pages остаётся архивом, после проверки индексации основного домена добавить noindex,follow к архивным HTML, сохранив доступ поисковикам для чтения директивы. Если это перенос, настроить постоянные перенаправления на соответствующие страницы там, где хостинг это поддерживает. Не заменять архивные страницы пустыми перенаправлениями без сохранения нужных функций.
7. Не пытаться управлять обходом через /GIFS/robots.txt: robots должен находиться в корне хоста /robots.txt. Отсутствие robots.txt само по себе не запрещает индексацию. Ничего не создавать в чужом корневом репозитории без проверки области действия.
