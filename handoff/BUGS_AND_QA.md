# GIFS — известные ошибки и QA

Снимки экрана пользователя многократно показывали яблоки в воздухе. Не подменять их «проверкой CSS» или автоматическим отчётом, который подтверждает только валидный HTML.

## Критические известные ошибки

1. **Яблоки вне веток.** Позиционирование через viewport %, неправильные нормализованные координаты и алгоритм collision avoidance давали плоды в воздухе. Вопрос решается разметкой реальных точек прикрепления ПЛОДОНОЖЕК на исходном изображении с последующей проверкой отрисовки `object-fit:cover` / `object-position`.
2. **Слишком много фруктов на ограниченной кроне.** Семияблочная `v13/` была забракована на пользовательских скриншотах. Текущий компромисс: 4 яблока + 3 направления как текст и карточки.
3. **Перевёрнутые яблоки.** Следить за фактической ориентацией `apple.webp` и вращением clone во время падения. Плодоножка вверх, не делать одновременно двойной поворот JS и CSS без проверки.
4. **Кликабельная зона под линией шапки.** Верхние плоды не должны попадать за логотип, `header`, псевдоэлементы или `overflow:hidden`. Тестировать реальным курсором и пальцем по всей видимой области.
5. **Обрезанный логотип GIFS.** Ballet имеет высокие штрихи: `padding`, `line-height`, реальная вертикальная позиция, safe-area, фон и `overflow`.
6. **Разные версии при переходе назад.** `/GIFS/v13/` однажды возвращала в `/GIFS/` с 4 яблоками, потому что внутренние страницы были общими. Все пути должны оставаться в актуальной папке и возвращать в её `index.html`.
7. **Ненужные цифры 01–07.** Убрать именно с fruit labels; разметка номера как декоративного элемента не нужна.
8. **CTA тяжёлого бордового цвета.** Пользователь категорически не хотел крупную винную плашку. Светлый CTA, акцентный винный только в мелочах.
9. **Слабое качество hero.** Старый `hero-loader.js` собирал webp base64 из TXT, скрывал img до JS и мог использовать изображение низкого разрешения. Нынешняя JPG — прямой источник.
10. **Ложное «готово».** GitHub Actions success/ZIP integrity не показывают ошибки композиции. Не заявлять визуальную проверку, если снимки реально не сделаны.
11. **Недоступное скачивание sandbox-файлов.** На стороне пользователя ссылки `sandbox:/mnt/data/...` в ChatGPT не запускали скачивание; поэтому создана эта отдельная GitHub ветка с обычным внешним архивом и браузерными Markdown-файлами.

## Чек-лист приёмки

- Открыть desktop 1457×873, 1440×900, 1280×800, 1024×768 и mobile 390×844, 360×640, 320×568.
- Для каждой точки показать, где находится ветка **над плодоножкой**, и проверить её во всех crop.
- Проверить 4 яблока по всей hit-area; никакой header/z-index не обрезает нажатие.
- Click → падение → нужный раздел → «К дереву» → тот же экран с 4 яблоками; повторить кнопкой браузера «Назад».
- Убрать пересечение яблок/подписей между собой, с текстом, шапкой и футером; сохранить читаемый правый блок.
- Логотип одинакового характера на всех страницах; без отсечения штрихов.
- Проверить `prefers-reduced-motion`, клавиатуру Tab/Enter/Focus и touch.
- Проверить наличие оригинальных ресурсов и лицензий, HTTP 200, ссылки `#sites`, `#chatbots`, `#ai`.
- Проверить отсутствие ложных заверений: контактный бриф не отправляется, если нет действующей интеграции.
- Зафиксировать реальные скриншоты QA с датой/размерами и отдельными наблюдениями по каждой проблеме.
